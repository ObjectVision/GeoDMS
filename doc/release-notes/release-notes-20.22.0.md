**Pre-release.** GeoDms 20.22.0 covers everything since **20.20.0**; the 20.21.0 and 20.21.1 builds in between were interim builds and their changes are folded in here. Headlines: the deferral of commits and IntegrityChecks that 20.20.0 introduced is withdrawn, so a run has its 20.19.x memory again and an item's `ExplicitSuppliers` are updated one after another, as before 20.20.0 (#1259); `pareto_optimal` and `pareto_optimal_eps` select the non-dominated rows of a table, and the pareto option of `impedance_matrix` takes an epsilon (#1281, #1282); the `dms_*` polygon operators are several times faster, and the split variants of every polygon family place the elements of a tiled domain correctly (#1283); a Pie Chart view (#1273) and a legend row for a layer drawn without a classification (#1274); an `.mmd` dictionary carries how its items are shown (#1275), and a missing store is an error (#1272); non-zero classifications that treat 0 as a break throughout, and Jenks-Fisher breaks for values far from zero; checked region ids in the allocation operators; 64-bit integers and NULL fields in `.dbf` files; and the fixes of a code audit of 2026-09-27, among them wrong results from `diversity`, `rounded_convert`, `corr` and the interaction results of `impedance_matrix`, and crashes in grid paste, `gdal.vect` and the Python binding.

## Things a modeller must act on

- **The 20.20.0 note "Memory under a deferred commit" no longer applies (#1259).** 20.20.0 let the walk over an item's suppliers go on while a stored item waited for its producer or an IntegrityCheck for its checker result, so that more producers ran side by side. Measured over the regression models, the deferral of checks never paid: it halved the wall time of one model at 346 GB of live memory, and cost an RSopen allocation model a quarter of its wall time at twice its commit (355 GB against 177 GB for 20.19.3). The deferral of commits gained 2.5 to 5 minutes on one group of models for up to 41 GB of live memory beyond the RAM, and cost 2 to 4 GB on others for no time at all. Both are gone: a commit waits for its producer and a check for its checker result, as before 20.20.0, and the walk updates an item's `ExplicitSuppliers` one after another, each completely before the next, as the ExplicitSuppliers page of the wiki describes. In the full regression round every model is back at its 20.19.x memory and the large models at their 20.19.x wall times; on one of the models the commit deferral served, the part of the 20.20.0 gain that did not come from the deferral stays (4:29 against 11:37 for 20.19.3, where the deferral had it at about 2 minutes). **Plan memory and run times on the 20.19.x figures, not on those of 20.20.0.** The columns of one `gdalwrite.vect` layer are still written together, which the storage manager does by itself (#1229). An interim build that started all the producers of a driver's `ExplicitSuppliers` at once was withdrawn as well: it failed a stored tif set with a self-referring check and tripled another model's memory.
- **Results that change on upgrade; the older numbers were the wrong ones.** `diversity` on a values unit whose range does not start at 0; `rounded_convert` to an unsigned type above the signed maximum; `corr` with a null in an argument; `modus_weighted` per partition with fractional weights; `modus` and its relatives per partition, counted in a table, where a value lies outside the range of its values unit (#1285); the interaction results of `impedance_matrix` with several start points on one node, several end points in one zone, or end points numbered differently from their zones; the split variants of every polygon family on a tiled domain (#1283); `bg_` results whose repair reversed a shell; `unique` and `direct_index` of bit values; `int64` and `uint64` columns read from a `.dbf` (all zeros before); a rotated georeference read through `gdal.grid`; `canyon` and the `points2sequence` family where the segment or sequence unit's range does not start at 0; the breaks of the non-zero classifications and of Jenks-Fisher on values far from zero; `modus_weighted` over the whole domain with a null weight; `max_index` and `min_index` where the extreme equals 0 (or the maximum of the value type); `interpolate_linear` with a negative integral result or a null in its x values; `regex_search` and `regex_match` with a flags argument; and `parse_xml` attributes that are missing after their last occurrence (0 before, null now). Each is described in its section below.
- **Configurations that ran without complaint may now stop with an error:** a read-only `.mmd` holder whose store or dictionary is missing (#1272); a number with an upper-case suffix such as `60D`, which now names a unit `D` (#1262); `cov`, `corr` or `modus_weighted` over the whole domain with arguments of two domains; a region id or atomic region outside its unit, or null, in `discrete_alloc`, `greedy_alloc` and `needy_alloc`; a duplicate ordinal in `points2sequence`; writing a rotated grid through `gdal.grid` or a world file; a Python `set_values_from_float_list` or `set_values_from_int_list` whose list does not hold one value per domain element; `cumulate` or `modus_count_uintN` where a partial sum or a count does not fit the values type, which used to wrap; and exactly 256 districts in `district_uint8` or 255 cells of a class in a region in `reg_count_uint8` (65536 and 65535 for the `uint16` variants). Several of these used to read or write out of bounds in a Release build. A `.dbf` column `N(11..19,0)` is now typed `int64` instead of `int32`.

## Storages

- **An `.mmd` dictionary carries how its items are shown (#1275).** For every item below the dictionary root it records `Descr`, `Label` and `DialogType`, and `DialogData` and `cdf` when every item they name lies inside the store; a reference by absolute path, or one that leaves the store, is left out, since under the reader's holder it would name something else or nothing. A `BrushColor` written with `DialogType = "BrushColor"` used to come back as a plain `uint32` attribute, and a store could not carry a visualisation style of its own. A dictionary written by an older version simply lacks these properties, and an older reader takes them as the ordinary properties they are.
- **A read-only `.mmd` holder fails when its store is missing (#1272)**, with *"MMD storage <dir> does not exist"* or, for a folder without a dictionary, *"has no dictionary <file>: the folder is not a complete MMD store"*: a red item and a nonzero exit from `GeoDmsRun`. It used to become an empty container that was ready and could never fail. A writer, for which a store that does not exist yet is normal, is unchanged.
- **`.dbf` files: 64-bit integers, NULL fields and wide columns.** An `int64` or `uint64` attribute read from a `.dbf` got 0 for every value without an error, and that is the type a modeller configures for ids of 16 to 18 digits; such values are now parsed as integers, exactly rather than through a `float64` that loses precision above 2^53, and are written like the other integers. A column `N(11..19,0)` is typed `int64`; `N(10,0)`, the usual width of an ESRI long integer, stays `int32`. A NULL numeric field, stored as blanks or as `*` fill by dBase, ESRI and shapelib/GDAL, reads as null; it used to fail the whole column with *"unexpected character"*.
- **`gdal.vect` reads mixed layers and stops leaking.** A `MultiPoint` read from a layer that also holds points, lines or polygons (GeoJSON, a CSV with a WKT column, a generic PostGIS geometry column) took a line or polygon for a multipoint: a crash or garbage. Each geometry now gives its own vertices as stored, a ring including its closing vertex, curves linearised and collections followed. Writing leaked every ring and polygon of an exported layer, about the size of the whole geometry column, and reading leaked a copy of every curved geometry (CurvePolygon, MultiSurface, CircularString, CompoundCurve; common in GML sources such as BGT and BRK) per attribute read. A read in several tiles no longer regrows its buffer from nothing for each tile.
- **A MultiPoint attribute can be written.** The shp storage manager wrote it as a Point shapefile without a single record and reported success; it now writes shape type MultiPoint, and refuses a composition that a shapefile cannot hold. `gdalwrite.vect` refused the attribute as a field of an unsupported type; it now writes a MultiPoint geometry.
- **A rotated georeference read through `gdal.grid` was transposed**; it now follows the build's point order and reduces to the axis-aligned result at zero rotation. Writing a rotated grid through `gdal.grid` or a world file is refused, where a Release build wrote it as axis-aligned with default terms. The `tif` storage still ignores a rotation.
- **A stored table's attribute read on demand is freed when its own interest drops (#587)**, as before 20.20.0, which kept it for as long as its table was in interest. With a table view open while eleven attributes of a 20 M row table were exported in turn: 1754 MB peak under 20.20.0, 991 MB now, as under 20.19.3.
- **The dataset information page of a `gdal.vect` or `gdal.grid` storage opens a dataset of its own**; it used to close the storage's dataset under a worker that was reading it. **CSV export of a database container** writes each table once, to `<export>/<table>.csv`; it rewrote the first table forever on the GUI thread, into a folder named after the whole file name. The shapefile reader and writer size their point stores beforehand.

## Polygons

- **The `dms_*` operators are faster (#1283).** An operation keeps one overlay engine from its first element to its last, or one per thread over its tiles; the sweeps, the noder index and the rings reuse their memory; and a single ring that is the only element of its slot is taken as it is, in the canonical form the sweep would give it. No result changes: that shortcut is taken only for a ring that is simple on the lattice, and a ring whose edges cross or touch (a bow tie, a vertex on another edge, a spike) goes through the sweep as before; an interim build took an asymmetric bow tie as it was and wrote a self-crossing ring. Measured step by step on 752,564 squares, `dms_split_polygon` went from 5.1 s to 2.5, 1.9 and finally 1.0 s (`geos_split_polygon`: 1.3 s); `dms_polygon` halved with the engine reuse alone; the single-ring shortcut took `dms_split_union_polygon(g, id(.))` from 3.3 to 1.2 s; on squares with a hole the memory reuse took `dms_split_polygon` from 7.0 to 4.7 s.
- **The split variants on a tiled domain put each element in its own slot (#1283)**, in all five families (`bp_`, `bg_`, `cgal_`, `geos_`, `dms_`). An unpartitioned element was placed by its index within its tile, so element k of every tile landed in slot k: `polygon_rel` ran from 0 to one less than the tile size, elements sharing a slot were unioned before being split again, and the slots beyond the largest tile stayed empty.
- **A `bg_` result no longer loses a polygon whose shell a repair reversed.** The winding-order repair reversed such an outer ring but kept its negative area, so its final test always found holes larger than the shell and removed the polygon it had just repaired. Reached from the `bg_` set operations and unions, the Minkowski operators and `clean_bg_geometry`.
- **`bp_` operators with a numeric argument** (`_filtered`, `_inflated`, `_deflated`, and the split and union forms) read that argument whole on a domain of several tiles, where they indexed a tile that does not exist. **`geos_buffer_linestring`, `geos_buffer` of an arc and `geos_simplify_linestring`** give an empty result for an empty arc instead of an access violation. **The `points2sequence` family** places points at their offset in the sequence unit: on `range(uint32, 1, 11)` the points of sequence v went to sequence v+1, or the operator threw a misleading *"unexpected orderNr"*; a duplicate ordinal, which left a point uninitialised, is now an error.

## Allocation

- **A region id outside its partitioning unit is an error** in the 10- and 11-argument forms of `discrete_alloc`, `greedy_alloc` and `needy_alloc`: *"Value 7 for atomic region 2 out of range [0, 2) of the regions of [[/RegA]]"*, or *"Value null ..."*, where it used to be an assertion in Debug and a write out of bounds in Release. A partitioning attribute was also read from its first tile only, so on an atomic region unit made by `TiledUnit` the regions of the other tiles were uninitialised; every tile is read now. The id is still taken as an index from 0, so on a partitioning unit whose range does not start at 0 the highest values of that range are rejected.
- **A narrow atomic region type no longer wraps the count of regions.** With a `uint8` atomic region unit, a region unit of 300 and another of 1, the 301 unique regions wrapped to 45 and all three operators failed on a valid configuration; with `uint16` from 65,536 unique regions on.
- **`greedy_alloc` and `needy_alloc` check the atomic region of every land unit** before anything is allocated, as `discrete_alloc` did: *"Value 7 out of range of valid Atomic Regions"*, or *"Value 255 (a.k.a. null-value) ..."* for a null in a `uint8` unit. They read and wrote out of bounds in Release, and a null on a land unit below the threshold went unnoticed.

## Classification and counting

- **`ClassifyNonzeroEqualCount` makes 0 a compulsory break**, as `ClassifyNonzeroJenksFisher` does, with a class of its own when there is room, and classifies the negative and the positive values apart. On data with a 0 it used to give the breaks of `ClassifyEqualCount`: [-3, 1, 2] for -3..3 with six zeros in 3 classes, one class for the negative values and all the zeros. The palette editor's *Equal Counts non-zero* item called *Equal Counts* and now calls this operator: on -10..19 in 5 classes it gave [-10, -4, 2, 8, 14] and now gives [-10, -5, 0, 1, 11].
- **`ClassifyNonzeroEqualInterval`** no longer reads past the end on only negative values, which now get the breaks of `ClassifyEqualInterval`; divides the classes over the two signs so that the widest class is as narrow as possible ([-100, -50, 0, 1, 2] in 4 classes: [-100, -75, 0, 1] instead of [-100, 0, 1, 1.5]); and treats 0 as the other two non-zero operators do: data that straddles 0 without containing it gets an empty class at 0 from 3 classes on, so that a diverging palette is anchored there, and in 2 classes a 0 beside values of one sign gets a class of its own (0..7: [0, 1] instead of [0, 3.5]).
- **`ClassifyNonzeroJenksFisher` in 2 classes on negative values and a 0** gives [minimum, 0]. It stopped a Debug build and built a classifier of 0 classes in Release, or, with a single positive value, gave [0, p] and left every negative value unclassified.
- **Jenks-Fisher breaks for values far from zero.** The break search summed uncentred values, so for values around -3e9 with a spread of 1000 its rounding exceeded the differences between candidate breaks and the breaks were noise, in Release too (a 4 % larger sum of squared deviations in 2 classes, 17 % in 3); likewise `uint64` around 5e9, `float64` around 1e12 and `int64` around 4e15. The sums are now taken relative to the weighted median, which moves no optimum; ordinary data give the same breaks, apart from a rare near-tie decided the other way. Two clusters far apart on either side of zero still exceed `float64` in `ClassifyJenksFisher`; `ClassifyNonzeroJenksFisher` splits them by sign. A Debug build no longer stops on breaks that tie up to rounding.
- **Integral values are counted, not sorted.** The two-argument `Classify` operators, `weeded_counts`, the map view's palettes and the total `modus` family count a tile's integral values with one counter per value where they lie close together, and bit values in a table of all their values; `unique` and its variants do the same. For 8 M `uint8` values in 10 classes the counting cost went from between 29 and 61 ms to within noise.
- **The `modus` family counts a value outside the range of its values unit like any other (#1285)**, whether a table or a set counts them, so the result no longer depends on which one does. Every integral variant (`modus`, `modus_count_uintN`, `unique_count_uintN`, `entropy`, `average_entropy`, `frequency_table`, `as_unique_list`, `modus_weighted`, in total and per partition) keeps its table over the range and counts such a value apart; the per-partition tables used to leave it out. Such values are data: a `switch` gives its result the values unit of its first case, and a later case may put a sentinel beyond that unit's range. The range now also picks the counting method, which lets the weighted tables run, 7 to 84 times faster than the sets. `modus_weighted` per partition compared its summed `float64` weights truncated, so a lighter value could win (1.2 over 1.5).
- **`modus_weighted` over the whole domain skips a null weight**, as the partitioned form did; the null made its value's total NaN, which won, after which every later value beat it: values [1, 1, 2] with weights [5, null, 1] gave 2. **`modus_count_uintN`** reports a count that does not fit its type, as `count_uintN` does; 300 equal values gave 44 for `modus_count_uint8`.

## Other operators

- **`diversity` counts a value at its offset from the start of the values unit's range.** On `range(uint8, 10, 15)` nothing was counted; on `range(uint8, 2, 7)` the values 0 and 1, below the range, were counted and 5 and 6 were not. Ranges that start at 0, among them that of a values unit declared without a range, give the same results as before.
- **`rounded_convert` to an unsigned type** rounded in the signed type of the same width and clamped there: `rounded_convert(200.2, uint8)` gave 127, 40000.4 into `uint16` 32767, 3e9 into `uint32` 2147483647, and point types likewise per coordinate.
- **`corr` leaves a row with a null in either argument out of every sum**; such a row was left out of the counts and products but not out of the sums of squares, so a float null made the result null and an `int32` null pulled it close to 0 without a warning. **`cov`, `corr` and `modus_weighted` over the whole domain** require both arguments on one domain, as their partitioned forms did; a second argument on a smaller or differently tiled domain was read out of bounds.
- **`invert` and `invertAll`** invert a null that lies inside the values range, where a Release build skipped it and wrote values from outside the range at unchecked positions; bit values on a domain of several tiles no longer stop a Debug build. **`unquote` and `undquote` of a lone quote character** give null; they read on into the next values. **`join_equal_values_uint8` and `_uint16`** report an overflowing count on the sparse path, taken for instance for a plain `uint32` key, as the dense path does; 300 occurrences wrapped to 44 and the fill corrupted the heap.
- **`canyon`** held its segment arguments only through temporaries, so a tiled or lazily computed argument was read from freed memory, and it indexed the segments by the raw value of the relation: a null (an unmatched `rlookup`) read far out of bounds, and a segment entity whose range does not start at 0 read the wrong segment. A null or out-of-range relation now gives the point no street.
- **Appending to a vector of bit values lost the values already in it**, since 17.6.0: the traceback of the border cells that a tiled `griddist` seeds its tiles with and, since 20.10.0, `unique` of sorted bit values and `direct_index` of bit values.
- **`cumulate`** stored each partial sum into the values type unchecked: `cumulate` of `uint8` [200, 100] gave [200, 44], and an `int32` sum past 2^31 wrapped. Such a sum is now an error, as it is for `sum`.
- **`max_index` and `min_index`** returned null where the extreme equals the start of their search, 0 for `max_index` of unsigned or boolean data (all zeros, in the whole domain or in a partition), and the maximum of the value type for `min_index`.
- **`ordinal`** of 8-, 16- or 64-bit values, or of `ipoint` or `upoint` values, stopped with an internal error; it now gives its `uint32` numbers for every value type.
- **`interpolate_linear`** gave null where an integral result is negative (a y of -10 and -20 at x 0 and 10 gave null at 5), and a null among the x values was taken for a real x, so a value below the first x was interpolated against it (0 instead of the first y). Null x values are now left out.
- **`regex_search` and `regex_match` use their flags argument**, which they ignored: every call ran with the default flags.
- **`parse_xml`** gives null to every entity in which an XML attribute does not occur; after the attribute's last occurrence, and throughout when it never occurred, it gave 0 or an empty string.
- **`get_x` and `get_y` of a null integer point** gave a number (-2147483648 for an `ipoint`); they now give null, as for a float point.
- **`district_uint8` and `reg_count_uint8`** (and their `uint16` twins) stored the count after the largest one as the null value: exactly 256 districts gave a unit without elements, and 255 cells of one class in a region a null count. Both now report the overflow.

## Networks

- **`pareto_optimal(partition_rel, crit1, ..., critN)` (#1281)** marks the rows that no other row of the same partition weakly dominates, by one sort and a sweep instead of comparing every row with every other: an `attribute<bool>` over the arguments' domain, one to eight criteria of any numeric type compared as `float64`, exact duplicates keeping their first occurrence, a null partition or a null or NaN criterion never optimal and dominating nothing. On a car store of 4,381,117 routes in 78,717 OD pairs, `unique`, `rlookup` and `pareto_optimal` took 0.2 s where the self-join formulation materialised 396 million pairs in 5.0 s, with the same rows marked.
- **Epsilon-dominance (#1282).** The pareto option of `impedance_matrix` takes an optional width, `pareto(imp2_epsilon)` or `pareto(OrgZone_max_imp2, imp2_epsilon)`, one value or one per origin zone, in the unit of the second criterion: a node keeps at most one label per bucket of that width, the fastest, which bounds its front by `max_imp2 / eps`. The result approximates the exact front: every exact point has an accepted label at its node that is no slower and less than eps more expensive, though along a route those deviations can add up; the first row per OD pair stays the fastest. On a table, `pareto_optimal_eps(partition_rel, crit1, eps1, ..., critN, epsN)` keeps a subset of what `pareto_optimal` keeps, and every optimal row it drops has a surviving row in its partition that it beats by less than eps, if at all, on every criterion; on the car store above a width of 10 cent keeps 1,329,016 rows.
- **The interaction results of `impedance_matrix`** (the potentials, `D_i`, `M_ix`, `C_j`, `M_xj`, `Link_flow`, `OrgZone_MaxImp`) are corrected in three cases. The `Link_flow` walk ran once per start point of an origin zone, so a start point reached more cheaply through another, or a second start point on the same node, added every potential and link flow twice. With `endPoint(Node_rel, DstZone_rel)` every reached end point of a zone took the zone's result slot, not only the one that claimed it, which multiplied the flows by the number of connectors per zone, or read a stale slot of an earlier origin in the sparse regime. And the arrival impedance of an end point was looked up by destination zone, so wherever end points and zones are numbered differently every result used another end point's impedance or read out of bounds.
- **`strongly_connected_components` ignores a link whose to-node is null or out of range**, as `connected_parts` does; a null `to_node_rel` was a write out of bounds in Release.

## Robustness

- **The low-RAM brake keeps work moving (#1259).** Above `MemoryFlushThreshold` (80 % machine RAM load by default) the scheduler activates no more operations of a phase than there are threads waiting in a join. With nobody waiting that was none, so work scheduled by a consumer that does not join, as the deferred commits of 20.20.0 did, sat idle until the RAM use dropped: about a second per stored item. The brake now keeps at least one operation of the phase activated or running. A worker that waits for an operation the brake held back now runs it itself; it used to poll every 500 ms until the RAM use dropped, which may never happen while its own process holds the memory.
- **Resource-aware scheduling (`/SQ`, `/Sq`)** estimates an operation from a copy of its own arguments; it fetched them on a worker thread through a call that may run on the main thread only, which stopped a Debug build at the first operation and raced the main thread in Release. A cancelled or failed operation is taken out of its suppliers' waiter lists; it stayed there and was failed once more when such a supplier failed later.
- **Python binding (#1279).** `fail_reason()` on an item that had not failed took the process down with an access violation; it now returns an empty string, as documented, and is on `MutableTreeItem` too. `update_metainfo()` determines an item's meta information without calculating anything and returns whether the item did not fail, the rule by which the TreeView colours an item red; with `in_template()` and `is_template()` a script can walk a configuration for red items. `set_values_from_float_list` and `set_values_from_int_list` write one value per domain element, tile by tile: a longer list, or any domain of more than one tile, was written past the end of the first tile, a shorter one left the rest undefined, and a list of another length is now an error.
- **Statistics of a string attribute on a domain whose tiles leave gaps** (`TiledUnit(lb, ub)` with ranges that do not cover it) read the tile data for a row in a gap, an index far out of bounds; such a row now counts as null.
- **Defects in the engine's own containers and strings** are fixed where no operator reaches them yet: appending or inserting an element of the container itself, inserting before the end, shrinking an owning array, growing a string (reached only by an ODBC connection string longer than 1024 bytes, whose second connect still fails), a quoting routine that unquoted, an index operator that called itself, and six defects in the packed bit containers. Container capacities between 8 KB and 1 MB fill the block the allocator commits for them, so they reallocate less often. A libtiff error or warning longer than 299 characters was formatted from garbage arguments on Linux, and one of exactly 300, 600 or 1200 characters lost its last character on every platform.

## Charts and views

- **Pie Chart (#1273)**, a fifth chart in the View menu and the TreeView pop-up, for a numeric or boolean attribute over a real domain: every row a slice of the total, clockwise from twelve o'clock in row order, with its percentage inside when it fits, and a *Pie / Donut* toggle that shows the total in the hole. Colours come from a `BrushColor` under the attribute or its domain, else the system palette; nulls and negative values are neither drawn nor counted, and one log line says how many were skipped; a boolean counts every true as one. The legend lists the domain's `Label`, the value and the percentage; the selection is shared with table and map views, and a slice clicked in the pie recolours at once. Several pie layers in one chart become concentric rings. For scripts: `SEND 12 1 4`.
- **A layer without a classification shows its colours in the Layer Control (#1274).** A point, arc or polygon attribute drawn in the map's default colours, or in a constant `BrushColor`, `PenColor` or `SymbolColor`, gets one legend row with those colours. 20.19.3 showed nothing for more than 32 features, 20.20.0 one identical row per feature. A grid layer without a palette is not covered.
- **Pasting cells into a grid layer is repaired.** Every paste freed the pasted values through an allocator that had not allocated them: a Debug build stopped on every paste, and in Release a block of 8 KB to 1 MB was later handed out again as the allocator's own. Dropping a floating paste (*Paste Selected Cells from Clipboard*) deleted the view's viewport and layer a second time; closing the view while a paste is pending now discards the paste and restores the cursor; a direct paste (Ctrl+Alt+P) or a second floating paste replaces a pending one; a direct paste that failed no longer stays drawn until the next paste. A grid that shows an attribute of its features through a grid of feature ids refuses both paste commands with *"Cannot paste to Indirect Grid"* before anything changes, and its pop-up no longer offers the paste, nor *Select District*, which read and wrote such a grid beyond the ends of its attributes. *Select District* also ignores a click outside the grid and no longer starts from a shifted cell on a grid whose range does not start at (0, 0).
- **A generated classification settles between two update cycles of its view (#1248)**, not inside a draw, where it invalidated the layer being drawn and, depending on timing, stopped a Debug build. **Closing or reloading a configuration no longer deletes the *Calculation times* window**, whose next report of two seconds or more then crashed the GUI, as did reopening it. The four status-colour buttons of the options dialog ask under their own option's name, and on Linux a persistent override survives *Apply*. An `.adms` page opened from a detail page is built without copying the page for every `<% %>` marker (8 MB with 400 markers: 2.5 s to 0.6 s in a Debug build).
- **A WMS background layer gives up on a server that stops answering.** A tile request whose connection, handshake, request or response stalled (a dropped network, a VPN reconnect, sleep) lived for ever: after eight of them no tile loaded for the rest of the session, and closing the map view, exiting, copying the view or exporting it waited for them on the GUI thread without end. A step of a tile request now gives up after 20 seconds, a closing view ends its own requests at once, and a WMS legend is fetched within 10 seconds or not at all.

## Configuration language and diagnostics

- **Literal suffixes are text, matched case-sensitively (#1262).** `60D` is no longer 60 as a `float64` but 60 in a unit named `D`, as `5m` is 5 in the unit `m`, and an unknown identifier where there is no such unit; the upper-case spelling was never documented. The suffix letters used to be registered as names, so every configuration with an item named D, F, U, I, W, S, B or C (a type parameter `D: domains`, a unit `W`, a container `C`) reported a case mix-up on every run. The engine's own names follow the spelling the configurations use: the member of `weeded_counts` and the palette's count attribute are `count`, the storage types `fss` and `mmd`, and a dump writes `range`; a configuration that wrote `Count`, `"FSS"` or `"MMD"` is now the one that differs in case. The shipped library and `prelude.dms` follow their own declarations.
- **The XML configuration notation decodes an entity reference in an attribute value.** Since 20.20.0 every attribute value is decoded, and one holding `&amp;` or `&quot;`, which the XML writer itself produces, hung the load. An unknown entity is kept as it stands.

## Packaging and build

- **Every shipped `.dms` is tested before a setup is packaged (ObjectVision/GeoDMS-Test#24)**, from the output folder and again from the installed copy, and a shipped file that no test case includes stops the setup. The extended test cases found a defect in the shipped library: `grids.dms` declared the cell areas `NrHaPerCell`, `NrKm2PerCell` and `NrMeter2PerCell` in units that resolved nowhere, so they could not be computed in any shipped configuration; they now use `units/ha`, `units/km2` and `units/meter2`.
- **`examples\convex_hull.dms`** ships the wiki's convex hull script (one ring, no holes, clockwise order) with checks on the hull points and areas. **The Windows uninstallers remove `prelude.dms`**, and those of `.m` and `.g` the shipped library and example files, so the install folder no longer stays behind.
